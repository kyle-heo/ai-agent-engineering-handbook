## 1. Executive Summary

AI 에이전트는 하나의 제품이 아니라 모델 추론, 오케스트레이션, 도구 실행, 메모리, 권한·보안, 관측 및 평가를 결합한 시스템이다. 큐레이션 목록은 후보 발견에 유용하지만 운영 도입 결정에는 최신 유지보수 상태, 라이선스, 기능 검증 및 비용 산정이 추가로 필요하다.

**핵심 판단**

1. 로컬 추론은 데이터 통제와 반복 호출 비용 측면에서 가치가 있으나 하드웨어·전력·운영비까지 포함하면 완전한 무비용은 아니다.
2. 에이전트 프레임워크는 상태 복원, 사람 승인, 장기 실행, 외부 도구 호출에 대한 요구로 선택해야 한다.
3. 코딩·컴퓨터 사용 에이전트에는 실행 격리와 권한 최소화가 선행되어야 한다.
4. GitHub Star는 관심도의 지표이지 성능, 보안, 유지보수 보증이 아니다.
5. 원문 추천의 AutoGen은 공식 저장소가 아카이브되었으므로 신규 도입 권고를 수정한다.

### 3.1 Ollama

로컬 추론 서버로서 모델 다운로드와 실행을 간소화한다. 데이터가 외부 API로 전송되지 않도록 설계할 수 있으나, 사용한 모델·플러그인·외부 연동의 네트워크 경로는 별도로 확인해야 한다. Mac Studio 환경에서는 기존 추론 엔진을 기준선으로 TTFT, tokens/s, 동시 요청, 메모리 점유, 모델 호환성을 측정한다.

### 3.2 LangChain과 LangGraph

LangChain은 LLM 앱의 다양한 구성 요소를 통합하는 데 유리하다. 반면 상태 복원, 체크포인트, 승인 단계 및 분기 실행이 핵심인 워크플로에는 LangGraph를 독립 평가한다. 두 기술은 동일한 비교 축의 완전한 대체재로 간주하지 않는다.

### 3.3 Open Interpreter

로컬 명령 실행을 허용하는 자동화는 효과가 크지만 작업 범위와 실행 권한을 잘못 설계하면 파일 변조 및 정보 유출 위험이 커진다. 테스트 전용 사용자, 격리 컨테이너, 제한된 마운트, 명령 승인 및 감사 로그가 필요하다.

### 3.4 AutoGen — 중요 정정

Microsoft의 [공식 AutoGen 저장소](https://github.com/microsoft/autogen)는 프로젝트가 아카이브되었으며 버그 수정·보안 패치·신규 기능·지원을 제공하지 않는다고 안내한다. 신규 프로젝트는 [Microsoft Agent Framework](https://github.com/microsoft/agent-framework)를 사용하도록 권고한다. 따라서 원문의 '먼저 설치할 다섯 가지'는 **역사적 원문 선정**으로만 기록하고, 실제 신규 도입 후보에서는 교체한다.

Microsoft Agent Framework의 A2A·MCP·워크플로 지원은 공식 문서에 소개되어 있으나, 기존 TypeScript/Rust 시스템과의 호환성은 별도 PoC로 확인해야 한다.

### 3.5 Aider

Git 저장소에서 변경을 추적할 수 있는 코딩 보조 도구다. 코드 현대화 작업에 활용할 경우 빌드·테스트·정적 분석을 통과한 변경만 승인하도록 구성한다. 자동 커밋 여부와 동작은 사용 설정을 확인해야 한다.

## 5. 실무 아키텍처

일반적인 에이전트 시스템은 다음 계층으로 구성할 수 있다.

1. **사용자 경험:** 웹·모바일 UI, 스트리밍, 사용자 승인.
2. **오케스트레이션:** 작업 상태, 재시도, 분기, 실행 기록.
3. **모델 계층:** 로컬/클라우드 추론, 모델 라우팅, 구조화 출력.
4. **도구 계층:** API, MCP, 브라우저, 파일·코드 실행.
5. **지식 계층:** 검색, 장기 메모리, 권한별 데이터 접근.
6. **안전·운영 계층:** 최소 권한, 샌드박스, 추적, 평가, 감사.

모든 제품을 동시에 도입하기보다 기존 구성 요소를 재사용하고 빠진 계층만 보완하는 편이 비용과 운영 복잡도를 줄인다.

## 6. 프로젝트 적용 전략

### 6.1 Agent Communication Bridge (ACB)

**목표:** 서로 다른 에이전트 간 메시지 연결과 세션 유지.

- 검토 후보: Microsoft Agent Framework의 메시지·상호운용 모델, LangGraph의 상태 모델.
- 확인 항목: 메시지 순서, 중복 제거, 재전송, 재연결, 타임아웃, 접근 권한, 장애 복구.
- 판단: 기존 TypeScript Core/Rust Runtime을 바로 교체하지 않고 비교 검증 후 선택.

### 6.2 SyncShift

**목표:** 레거시 코드 분석·변환·검증의 반복 가능한 자동화.

- 권장 흐름: 소스 분석 → 변환 규칙 선정 → OpenRewrite → LLM 보완 → 빌드·테스트 → 승인.
- 후보: LangGraph(실행 상태), DSPy(최적화), Aider(변경 작업 참고).
- KPI: 컴파일 성공률, 테스트 통과율, 변환 정확도, 수동 수정률, 처리 시간.

### 6.3 사내 업무 AI 포털

**목표:** 문서 검색, 회의록 처리 및 업무별 AI 기능 제공.

- 후보: Flowise(워크플로 PoC), mem0(장기 메모리), Vercel AI SDK(UI).
- 선결조건: 인증·권한, 문서 접근 통제, 개인정보 보존 기간, 감사 로그.
- 판단: 포털 전체를 교체하지 않고 구성 요소별 도입 효과를 검증.

### 6.4 로컬 추론 및 음성 AI

- Ollama는 기존 로컬 추론 환경과 성능·메모리·호환성 비교.
- 음성 서비스는 한국어 STT, 화자 분리, TTS 지연, 월 처리량 기준 비용을 비교.
- 외부 음성 API 사용 시 데이터 전송·보존 조건을 검토.
